# Optional assessment freshness

Install the freshness extra and import assess_with_freshness from open_rosetta.freshness. It returns the original Assessment, an independent freshness observation, a reason and a permanently false authorizes_execution property. Existing assess callers and governed-backend pins keep their existing contracts. A fresh set of evidence can describe a failed constraint.

The trusted publisher computes assessment_subject on independently obtained evidence. Bind the policy's actual version and content SHA-256. The subject also covers assessment profile, schema, all six request binding fields, and every ordered observation's check, value, reference and binding. A caller-supplied digest echoed by a signing service cannot establish temporal validity.

For online checks pass an enrolled syzygy_freshness.Verifier and its host-supplied exchange. Missing or unverified evidence remains visible alongside the original verdict. For an explicitly accepted, content-free bounded preview pass preview_max_age_ms and omit exchange. An online error never silently downgrades to a preview. Neither mode creates a ticket for the governed adapter. The host must independently decide whether and how to act at its actual admission boundary.

This integration builds on Zixuan Guo’s freshness protocol research. See the draft protocol's FRESHNESS_OBSERVATION.md for trust, enrollment, clocks, rollback and recovery. There is no service endpoint, credential distribution or billing change.
